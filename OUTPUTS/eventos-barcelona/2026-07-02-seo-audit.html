Top 5 quick wins — orden de ejecución recomendado

QW1 — Consolidar duplicate hub /musica/ ↔ /grupos-musica/

Severidad: Blocking Esfuerzo: 30-60 min (decisión) + 15 min ejecución Impacto: Alto · afecta N2 principal + 20 páginas N3

Qué encontramos: Existen dos hubs de música con el mismo title, mismo H1 y ambos apuntan su canonical a /grupos-musica/. Es decir, /musica/ es SEO-invisible aunque exista físicamente. La pirámide biblia dice que /musica/ es el N2 primario — hay contradicción entre lo que el doc canónico afirma y lo que Google ve.

El menú del header linkea a /grupos-musica/. Las 19 de 20 páginas N3 de música están linkadas desde /musica/ (la muerta) y también desde /grupos-musica/. La autoridad se está dispersando.

Fix (decisión editorial primero, ejecución después)
  1. Decidir cuál es la URL oficial. Opción recomendada: consolidar en /musica/ (más corta, coherente con la pirámide biblia, coherente con /danza/, /artistas/, /espectaculos/). Alternativa: aceptar /grupos-musica/ como canonical y actualizar la pirámide.
  2. Configurar 301 redirect /grupos-musica/ → /musica/ (via Redirection plugin o Yoast Redirect).
  3. Actualizar el menú Elementor del header para linkear a /musica/.
  4. Actualizar el canonical del contenido consolidado a self.
  5. Regenerar sitemap y forzar re-crawl vía GSC.

QW2 — Broken link /.md en TODAS las páginas

Severidad: Important Esfuerzo: 5 min Impacto: Bajo por página · alto por volumen (296 URLs)

Qué encontramos: Cada página del sitio emite en el head <link rel="alternate" type="text/markdown" href="https://www.eventosbarcelona.com/.md">. Esa URL devuelve HTTP 404. Es un bug del snippet Code Snippets EB-AUDIT-100 (id 13) — la variable de URL quedó vacía y concatenó /.md.

Efecto real: broken link en el head de las 296 URLs → warning menor en crawlers, y podría confundir a agentes AI que sigan el link markdown.

Fix
  1. Editar snippet EB-AUDIT-100 en /wp-admin/admin.php?page=snippets.
  2. Corregir la línea que emite el <link rel="alternate" type="text/markdown"> para que use la URL actual + .md (o quitarlo — el markdown endpoint real está en /wp-json/eb/v1/page-md).
  3. Guardar. Purgar cache WP-Optimize.

QW3 — LocalBusiness schema duplicado en todas las páginas

Severidad: Important Esfuerzo: 5 min Impacto: Medio · schema warnings en Google Search Console

Qué encontramos: En el head del sitio hay 2 bloques JSON-LD de tipo LocalBusiness. Uno viene del snippet EB-SCHEMA-LOCALBUSINESS (id 10) que añadimos, otro viene de Yoast en su @graph. Ambos son sintácticamente válidos pero Google recomienda un único LocalBusiness por página.

Fix
  1. Desactivar snippet EB-SCHEMA-LOCALBUSINESS (id 10) desde /wp-admin/admin.php?page=snippets. Yoast ya emite un LocalBusiness completo dentro del @graph, no hace falta el redundante.
  2. Validar en Rich Results Test post-cambio.

QW5 — Activar IndexNow en Yoast Premium

Severidad: Nice Esfuerzo: 2 min Impacto: Medio · notificación instantánea Bing/Yandex de nuevo contenido

Qué encontramos: /indexnow.txt devuelve 404 — el key file de IndexNow no está publicado. Yoast Premium incluye IndexNow como toggle y no está activado.

Especialmente relevante para la fase de publicación jul-ago (24 páginas nuevas): con IndexNow activo, Bing/Yandex descubren el contenido en minutos vs días.

Fix
  1. WordPress admin → Yoast SEO → General → tab IndexNow.
  2. Activar el toggle. Yoast genera el key file automáticamente.
  3. Verificar curl -sI https://www.eventosbarcelona.com/indexnow.txt devuelve 200.

Handoff briefs · Accessibility + Performance code

Handoff Brief 1 — Render-blocking CSS/JS (impacto en LCP)

Métricas: LCP (Core Web Vitals) Location: Home + todas las páginas Elementor Stack: WordPress + Elementor + Perfmatters

Root cause: Home carga 30 archivos CSS + 21 archivos JS externos. Perfmatters está activo pero no está agrupando los assets. Elementor genera CSS por widget, WPML añade su propio CSS, Yoast agrega otros. El navegador debe descargar y parsear todo antes del first render.

Fix:

  1. WP admin → Perfmatters → tab Assets → activar "Combine CSS" y "Combine JS" (validar en staging que no rompa layout Elementor).
  2. Perfmatters → tab Assets → Script Manager: identificar plugins que cargan JS en el frontend innecesariamente (WooCommerce si aún está instalado sin usarse, Contact Form 7 en páginas sin form, etc.) y desactivarlos por página.
  3. Elementor → Settings → Performance → activar "CSS Print Method: External file" + "Google Fonts Load: Swap".

Verification: Volver a correr PageSpeed en 24h. Objetivo: mobile score ≥85.

Files probables: wp-content/plugins/perfmatters/perfmatters.php (settings via admin, no edición directa). Elementor: wp-admin → Elementor → Settings.

Handoff Brief 2 — Conversión masiva de imágenes a WebP (impacto en LCP + AI visibility)

Métricas: LCP, page weight, GEO image_formats check Location: /wp-content/uploads/ (7984 JPG + 573 PNG) Stack: WordPress · hosting CDmon (sin ImageMagick automático)

Root cause: Solo <1% de las imágenes del sitio tienen versión WebP. El resto siguen sirviéndose como JPG/PNG. Peso de página 193KB en home a pesar de que el HTML es limpio — el problema es imagen.

Fix (opciones ordenadas por coste):

  1. Cloudflare gratis (recomendado): poner el dominio detrás de Cloudflare (DNS proxy). Con Polish activo (free tier) convierte imágenes on-the-fly a WebP según Accept-Encoding del browser. Cero coste, cero cambio en WP.
  2. WebP Express (plugin gratis WP): instala convertidor local + .htaccess rewrite. Requiere binarios de imagen en el hosting (verificar con CDmon).
  3. Imagify / ShortPixel (freemium): 100-500 imgs/mes gratis, luego pago. Para 8000+ imgs sale a pagar.

Files probables: Cloudflare no toca WP. WebP Express instala en wp-content/plugins/webp-express/.
